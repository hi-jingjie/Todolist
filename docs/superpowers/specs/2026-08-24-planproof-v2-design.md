# PlanProof V2 设计规格

## 背景

`v1.0.0` 是一个本地优先的微信小程序待办与专注工具，支持任务、分类、优先级、截止日期、专注计时和统计，但不依赖服务端。

V2 将其演进为 PlanProof：面向大学生和求职者的证据驱动 AI 任务规划器。它把一段通知文本转换为用户可确认的任务草稿；每个事实都能回看原文依据，并通过真实完成数据逐步校准计划。

## 目标

1. 从课程、作业、比赛或求职通知中提取结构化任务草稿。
2. 为截止日期、要求和不确定项提供原文证据，避免模型编造事实。
3. 仅在用户确认后写入本地待办；AI 不直接修改用户数据。
4. 基于截止日期、预计耗时和可用时间生成无冲突的每日计划。
5. 根据预计与实际耗时，提供可解释的个人校准数据。
6. 以匿名固定样本评估提取、引用和计划质量。

## 非目标

- V2 不支持截图 OCR、PDF 解析、微信群或邮件自动导入。
- V2 不做云端任务同步、账号体系、多人协作或自动发送提醒。
- V2 不让模型代表用户执行写入、删除、提交或外部操作。
- V2 不使用多智能体或长期记忆。

## 目标用户与核心场景

目标用户是有课程、求职和活动截止日期压力的大学生。用户从群公告、课程通知或招聘信息复制文本，粘贴到 PlanProof；应用提取事项和证据，用户编辑并确认；应用把任务放入待办、建议现实日计划，并在完成后记录实际耗时。

## 产品流程

```text
粘贴通知文本
  -> CloudBase 云函数调用 LLM
  -> 返回任务草稿、证据和不确定项
  -> 本地校验证据与结构
  -> 用户确认或编辑
  -> 写入本地任务数据
  -> 确定性规则生成今日计划
  -> 记录完成结果与实际耗时
  -> 更新个人估时校准
```

## 架构

### 小程序客户端

现有小程序仍是用户数据的主存储位置。新增两个页面：

- `pages/ingest/`：输入通知文本，显示任务草稿、证据和不确定项，并接收用户确认。
- `pages/plan/`：显示今日可执行计划、冲突原因和预计/实际耗时反馈。

客户端负责本地数据读写、交互、确定性校验和离线降级；不保存 LLM API Key。

### CloudBase 云函数

新增 `cloudfunctions/task-extractor/`。这是无状态 Node.js/TypeScript 服务，负责验证文本长度和请求结构、从 CloudBase Secret 读取模型凭证调用 LLM、解析 JSON、执行 Schema 校验并返回草稿或可显示的错误。

云函数不保存通知原文、任务、用户画像或完成记录。密钥只存在 CloudBase Secret 中；开发环境使用未提交的 `.dev.vars` 文件。

### 规则核心

`utils/plan-proof/` 保存不依赖 UI 或网络的纯函数：输出 Schema 与字段规范化、证据片段验证、草稿到本地任务的转换、容量与冲突校验、预计耗时和实际耗时的校准计算。规则核心必须可被 Node.js 测试直接调用。

## AI 输出契约

每个候选任务必须包含：

```text
title: string
dueAt: ISO 日期时间或 null
priority: low | medium | high
estimateMinutes: 正整数或 null
evidenceQuote: string
confidence: 0 到 1
uncertainties: string[]
```

- `evidenceQuote` 必须是输入原文的非空连续子串；否则草稿无效。
- 未知截止日期必须为 `null`，不能由模型推测。
- 置信度只用于提示，不能绕过用户确认。
- 任一 Schema、日期或证据校验失败的草稿都不能保存。

## 数据与隐私

已确认的任务、计划、实际耗时和校准统计继续在小程序本地存储。通知原文只在本次请求中发送给用户选择的模型服务；V2 不建立云端原文库。

已确认任务保留最小证据片段，供用户回溯 AI 的提取依据。评估样本必须手工编写或彻底匿名化，不得包含真实姓名、联系方式、学号、群聊内容或 API Key。

## 失败与降级

| 情形 | 用户可见行为 | 数据处理 |
| --- | --- | --- |
| 网络或模型调用失败 | 显示原因与重试入口 | 原文保留在输入框，不创建任务 |
| 非 JSON 或 Schema 不合法 | 提示“AI 结果不可用” | 不保存草稿 |
| 证据不在原文中 | 标记无效结果 | 不允许确认该项 |
| 信息不完整 | 标记“待确认” | 用户可补充后保存 |
| 当日排不下任务 | 展示超量原因与候选取舍 | 不删除、不静默移动任务 |

## 评估与测试

`evals/` 存放版本化、匿名的通知样本和人工期望结果，至少覆盖明确截止日期、相对日期、无截止日期、多个任务、非法 JSON、无效日期、虚构证据、超长输入和不可达计划。

持续检查任务和截止日期提取、证据引用、无效输出拦截、时间冲突、超容量计划及校准计算。现有 Node.js 断言测试保持可运行；新增规则和云函数适配层各自有回归测试。评估和单元测试必须能在无真实 API Key 的模拟模式下运行。

## 仓库结构

```text
cloudfunctions/task-extractor/  CloudBase AI 提取云函数
pages/ingest/                   通知导入与确认页
pages/plan/                     今日计划与反馈页
utils/plan-proof/               可测试的验证、排期与校准逻辑
evals/                          匿名评估样本与期望结果
tests/                          单元与回归测试
docs/                           架构、隐私、评估和使用说明
```

## 发布策略

从 `main` 创建 `codex/v2-planproof` 功能分支。V2 完成并验证后合并回 `main`，发布 `v2.0.0` Release。`v1.0.0` 标签保持为纯本地微信小程序版本的稳定基线。

## V2 成功标准

1. 用户可完成“提取 -> 确认 -> 本地保存 -> 计划 -> 反馈”的全流程。
2. API Key 不出现在小程序代码、提交历史、示例配置或日志中。
3. 每项已确认任务都有来自输入原文的有效证据。
4. 评估集与单元测试可在无真实 API Key 的模拟模式下运行。
5. README 提供本地运行、云函数配置、隐私边界、演示步骤和评估说明。
